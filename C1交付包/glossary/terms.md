# CS146S 现代软件开发者 (Vibe Coding) 核心技术术语规范指南

本术语规范为斯坦福大学 **CS146S: The Modern Software Developer** 全套中文教材与技术文档的标准化映射标准。为保证全篇翻译质量的一致性与学术专业性，所有机器与人工校对流程必须严格遵守本表定义的译法与规则。

---

## 一、AI 智能体与模型范式 (Agents & Models)

| 英文原词 (English) | 推荐中文译名 (Standard Zh) | 释义与语境 (Definition & Context) | 翻译与排版规则 (Rules) |
|---|---|---|---|
| **Vibe Coding** | **氛围编码（意图驱动编码）** | 开发者仅用自然语言表达高层意图与氛围感，由 AI 智能体负责绝大部分代码生成的编程新范式。 | 首次出现使用“Vibe Coding（氛围编码/意图驱动编码）”，后续直接保留英文 “Vibe Coding” 或简写为“氛围编码”。 |
| **Coding Agent** | **编程智能体** | 具备环境感知、工具调用、自主循环与代码读写能力的自主 AI 智能体。 | 严禁译为“编码代理人”，统一使用“编程智能体”。 |
| **Sub-agent** | **子智能体** | 由主智能体派生、负责专项子任务的独立智能体。 | 统一使用“子智能体”。 |
| **In-context Learning** | **上下文学习** | 大模型无需微调权重，仅通过上下文中的少量示范即可完成新任务的能力。 | 统一使用“上下文学习”。 |
| **Zero-shot Prompting** | **零样本提示** | 不提供任何示例、仅给任务指令的提示方式。 | 统一使用“零样本提示”。 |
| **Few-shot Prompting** | **少样本提示** | 在提示中提供若干输入-输出示例以引导模型按规律作答的提示方式。 | 统一使用“少样本提示”。 |
| **System Reminder** | **系统提醒机制** | 如 Claude Code 中的 `<system-reminder>`，在长对话中动态向上下文注入高优先级约束。 | 统一译为“系统提醒机制”，标签保留 `<system-reminder>`。 |

## 二、上下文管理与工程架构 (Context Engineering & Architecture)

| 英文原词 (English) | 推荐中文译名 (Standard Zh) | 释义与语境 (Definition & Context) | 翻译与排版规则 (Rules) |
|---|---|---|---|
| **Context Window** | **上下文窗口** | 模型在单次推理过程中能够接收并处理的最大 Token 序列长度。 | 统一使用“上下文窗口”。 |
| **Context Rot** | **上下文退化（上下文腐化）** | 随着长上下文填入大量无关或噪声信息，模型注意力分散、指令遵从度及推理准确率下降的现象。 | 统一使用“上下文退化”或“上下文腐化”，可附英文括号说明。 |
| **Model Context Protocol (MCP)** | **模型上下文协议 (MCP)** | Anthropic 发起的开放标准协议，用于连接 AI 模型与本地/远程开发工具、数据源和上下文环境。 | 首次出现为“模型上下文协议 (MCP)”，后续使用“MCP”。 |
| **MCP Server / Client** | **MCP 服务端 / 客户端** | 实现 MCP 协议的服务端程序与消费该能力的客户端（如 Claude Desktop, Cursor）。 | 统一使用“MCP 服务端 / 客户端”。 |
| **MCP Registry** | **MCP 注册中心** | 集中检索、发现与分发各类标准 MCP 工具与服务器的公开目录服务。 | 统一使用“MCP 注册中心”。 |
| **Tool Use / Function Calling** | **工具调用 / 函数调用** | 模型自主选择并调用外部 API 或按 JSON Schema 输出结构化参数的技术。 | 区分使用：“工具调用”侧重智能体能力，“函数调用”侧重底层协议机制。 |
| **PRD** | **产品需求文档 (PRD)** | 描述软件功能需求、业务逻辑与边界条件的技术文档，在 AI 时代作为智能体核心输入规格。 | 首次使用“产品需求文档 (PRD)”，后续使用“PRD”。 |
| **Specs** | **规格说明（规范文档）** | 详细的技术接口与行为约束规范；在“Specs are the new source code”中指顶层规范。 | 统一译为“规格说明”或“规范文档”。 |

## 三、安全与漏洞检测 (AI Security & Vulnerability)

| 英文原词 (English) | 推荐中文译名 (Standard Zh) | 释义与语境 (Definition & Context) | 翻译与排版规则 (Rules) |
|---|---|---|---|
| **SAST** | **静态应用安全测试 (SAST)** | 在不运行程序的情况下分析源代码、字节码以发现漏洞的安全检测方式（白盒测试）。 | 统一使用“静态应用安全测试 (SAST)”。 |
| **DAST** | **动态应用安全测试 (DAST)** | 在运行状态下从外部探测应用程序漏洞的安全检测方式（黑盒测试）。 | 统一使用“动态应用安全测试 (DAST)”。 |
| **Prompt Injection** | **提示注入** | 攻击者通过恶意输入劫持或覆盖大模型原有系统指令的安全漏洞。 | 统一使用“提示注入”。 |
| **Remote Code Execution (RCE)** | **远程代码执行 (RCE)** | 攻击者利用漏洞在受害者主机或容器内直接运行任意恶意命令的高危安全漏洞。 | 统一使用“远程代码执行 (RCE)”。 |
| **OWASP Top 10** | **OWASP Top 10 安全风险** | 开放式 Web 应用程序安全项目发布的十大最严重安全风险清单。 | 统一保留“OWASP Top 10”。 |

## 四、代码审查与工程实战 (Code Review & Development)

| 英文原词 (English) | 推荐中文译名 (Standard Zh) | 释义与语境 (Definition & Context) | 翻译与排版规则 (Rules) |
|---|---|---|---|
| **Tribal Knowledge** | **团队内隐经验（团队默会知识）** | 存在于资深员工心智中、未写入正式文档的代码库演进历史与非标准架构决策。 | 统一译为“团队内隐经验”或“团队默会知识”。 |
| **Code Review Reps** | **代码审查实战演练** | 借鉴健身“组数/次数(Reps)”概念，指针对多样化 PR 进行的高频次代码审查练习。 | 统一使用“代码审查实战演练”。 |
| **AI-native** | **AI 原生** | 自底向上为大模型与智能体协同而设计的软件架构、终端或开发流程。 | 统一使用“AI 原生”。 |
| **Agentic Workflows** | **智能体工作流** | 由自主规划、工具调用、自我纠错与多智能体协作组成的迭代执行流程。 | 统一使用“智能体工作流”。 |

## 五、SRE 与生产运维 (SRE & Observability)

| 英文原词 (English) | 推荐中文译名 (Standard Zh) | 释义与语境 (Definition & Context) | 翻译与排版规则 (Rules) |
|---|---|---|---|
| **SRE** | **站点可靠性工程 (SRE)** | 将软件工程原则应用于系统运维与基础设施可靠性保障的工程学科。 | 统一使用“站点可靠性工程 (SRE)”。 |
| **Observability** | **可观测性** | 通过系统外部输出（指标 Metrics、日志 Logs、链路追踪 Traces）推断内部运行状态的能力。 | 统一使用“可观测性”。 |
| **Trace & Span** | **链路追踪与跨度 (Trace & Span)** | 分布式系统中跟踪请求全生命周期的调用链与其中各个逻辑工作单元。 | 统一使用“链路追踪 (Trace)”与“跨度 (Span)”。 |
| **On-Call** | **轮值排障（On-Call）** | 工程师轮流待命以应对生产环境突发告警与故障修复的工作制度。 | 统一使用“轮值排障”或保留“On-Call”。 |
